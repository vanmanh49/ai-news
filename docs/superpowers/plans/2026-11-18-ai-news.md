# AI News Hub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public English-only GitHub Pages site that auto-collects AI news, tools and trending AI repos every 12 hours, with monthly history browsing.

**Architecture:** A GitHub Action runs `node scripts/fetch.js` on cron; it fetches sources from `config.json`, merges new items into `data/YYYY-MM.json` month files (never deleting), writes `data/index.json`, and commits. `index.html` (vanilla JS) loads `index.json` + one month file and renders tabs, search, month picker, day groups.

**Tech Stack:** Node 20+ (built-in `fetch`, `node:test`), `rss-parser` (only dependency), vanilla HTML/CSS/JS, GitHub Actions, GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-11-18-ai-news-design.md`

## Global Constraints

- English only. No translation, no API keys beyond the Action's built-in `GITHUB_TOKEN`.
- Only runtime dependency: `rss-parser`. No frontend framework, no build step.
- Default schedule: cron `0 0,12 * * *`, plus `workflow_dispatch`.
- History is never deleted. Storage is one file per month: `data/YYYY-MM.json`; `data/index.json` = `{ "updated": ISOString, "months": ["2026-11", ...] }` (months sorted desc).
- Item shape: `{ id, type, title, url, source, date, summary, stars? }`; `type` ∈ `news | tools | repos`; `id` = normalized URL; `date` = ISO string; `summary` plain text ≤ 200 chars.
- A failing source is logged and skipped; it never aborts the run or removes data.
- Git commit messages: no AI/Claude attribution of any kind (owner's global rule).

## Review Focus

1. **Untrusted feed text rendered on a public page** — titles/summaries containing `<script>` or `<img onerror>` must show as text; links with `javascript:` URLs must not be rendered as links. (Task 4 test: `render escapes html and drops non-http links`.)
2. **Same article, different URL spelling** (`utm_*` params, trailing slash, `#hash`, `http` vs `https` not merged) — must dedupe to one item. (Task 1 test: `normalizeUrl strips tracking, hash, trailing slash`.)
3. **Corrupt month file** (half-written JSON) — the run must abort with an error instead of overwriting it with a smaller file. Missing file = empty month. (Task 3 test: `run aborts on corrupt month file`.)
4. **Feed entry with no date or an unparseable date** — use the run time; never `Invalid Date` or a `NaN-NaN` month. (Task 2 test: `feedEntryToItem falls back to now for bad date`.)
5. **Repo seen again in a later run** — keep its original `date` and month, update `stars`; no duplicate in the new month. (Task 1 test: `mergeItems updates stars of existing repo in place`.)

### Task 1: Project setup + core merge logic

**Files:**
- Create: `package.json`, `.gitignore` (`node_modules/`), `scripts/lib.js`, `scripts/lib.test.js`

**Interfaces:**
- Produces (all named exports of `scripts/lib.js`):
  - `normalizeUrl(url: string) -> string` — lowercase host, drop `#hash`, drop query params starting `utm_` and `ref`, drop trailing `/` from path (except root).
  - `cleanText(html: string | undefined, max = 200) -> string` — strip tags, decode `&amp; &lt; &gt; &quot; &#39; &nbsp;` and numeric entities, collapse whitespace, trim, cut to `max` chars ending with `…` if cut.
  - `monthKey(iso: string) -> "YYYY-MM"` (UTC).
  - `mergeItems(months: Record<string, Item[]>, incoming: Item[]) -> { months, changed: Set<string> }` — dedupe by `id` across all months; new item goes into `monthKey(item.date)`; existing repo item gets `stars` (and `summary`) updated in place; existing non-repo items untouched; each changed month sorted by `date` desc. Does not mutate input.

- [ ] **Step 1:** `git init`, create `package.json` (`"type": "module"`, `"scripts": {"test": "node --test scripts/", "fetch": "node scripts/fetch.js"}`, `"engines": {"node": ">=20"}`), `npm install rss-parser`.
- [ ] **Step 2: Write failing tests** in `scripts/lib.test.js`:
  - `normalizeUrl strips tracking, hash, trailing slash`: `normalizeUrl("https://Ex.com/a/?utm_source=x&id=2#top")` === `"https://ex.com/a?id=2"`; `normalizeUrl("https://ex.com/")` === `"https://ex.com/"`.
  - `cleanText strips tags and entities and truncates`: `cleanText("<p>A &amp; <b>B</b></p>")` === `"A & B"`; `cleanText("x".repeat(300)).length` === 200 and ends with `"…"`; `cleanText(undefined)` === `""`.
  - `monthKey uses UTC`: `monthKey("2026-11-30T23:30:00-05:00")` === `"2026-12"`.
  - `mergeItems adds new items to their month and dedupes`: merging `[a(2026-11-02), a again, b(2026-10-05)]` into `{}` gives `months["2026-11"].length===1`, `months["2026-10"].length===1`, `changed` = {"2026-11","2026-10"}.

  - `mergeItems leaves existing news untouched and reports no change`: same news id again → `changed.size===0`.

### Task 2: Sources (feeds + GitHub) and config

**Files:**
- Create: `config.json`, `scripts/sources.js`, `scripts/sources.test.js`

**Interfaces:**
- Consumes: `normalizeUrl`, `cleanText` from Task 1.
- Produces (named exports of `scripts/sources.js`):
  - `feedEntryToItem(entry, feed: {name, url, type}, now: Date) -> Item | null` — `null` if entry has no http(s) link or no title. `date` from `entry.isoDate || entry.pubDate`, falls back to `now.toISOString()` if missing/unparseable. `summary` = `cleanText(entry.contentSnippet || entry.content || entry.summary)`. `source` = `feed.name`.
  - `repoToItem(repo, now: Date) -> Item` — from GitHub search API item: `title` = `full_name`, `url` = `html_url`, `summary` = `cleanText(description)`, `stars` = `stargazers_count`, `source` = `"GitHub"`, `type` = `"repos"`, `date` = `now.toISOString()` (first-seen).
  - `fetchFeed(feed, now) -> Promise<Item[]>` — `rss-parser` `parseURL`, 20s timeout, map + drop nulls.
  - `fetchGithub(gh: config.github, token: string | undefined, now) -> Promise<Item[]>` — one request per topic to `https://api.github.com/search/repositories?q=topic:<t>+created:><YYYY-MM-DD>+stars:>=<minStars>&sort=stars&order=desc&per_page=<perPage>`, headers `Accept: application/vnd.github+json`, `Authorization: Bearer <token>` if set; throws on non-2xx with status in the message.
- `config.json`:
  ```json
  {
    "feeds": [
      { "name": "Hugging Face", "url": "https://huggingface.co/blog/feed.xml", "type": "news" },
      { "name": "Google AI", "url": "https://blog.google/technology/ai/rss/", "type": "news" },
      { "name": "Google DeepMind", "url": "https://deepmind.google/blog/rss.xml", "type": "news" },
      { "name": "OpenAI", "url": "https://openai.com/news/rss.xml", "type": "news" },
      { "name": "Hacker News", "url": "https://hnrss.org/newest?q=AI+OR+LLM+OR+GPT&points=50", "type": "news" },
      { "name": "Show HN", "url": "https://hnrss.org/show?q=AI+OR+LLM&points=20", "type": "tools" }
    ],
    "github": { "topics": ["llm", "ai-agents", "generative-ai"], "createdWithinDays": 30, "minStars": 50, "perPage": 30 }
  }
  ```

### Task 4: The page (`index.html`)

**Files:**
- Create: `index.html`

**Interfaces:**
- Consumes: `data/index.json`, `data/<month>.json` (shapes in Global Constraints).
- Produces: none.

Behavior:
- Header: site title "AI News Hub", "Updated <relative time>" from `index.updated`.
- Controls: month `<select>` from `index.months` (first = default; also read/write `?month=YYYY-MM` in the URL so a month is linkable), tabs All / News / Tools / Repos (`<button aria-pressed>`), search `<input type="search">` filtering title + summary + source, case-insensitive, within the loaded month.
- List: grouped by day (UTC date of `item.date`) under `<h2>` like "Wed, 18 Nov 2026"; card = title link (`target="_blank" rel="noopener"`), source · relative time, summary, `★ 1.2k` for repos.
- Empty states: "No items yet" (no months), "No matches" (filters hide all). Fetch error → "Couldn't load data".
- Rendering built with `document.createElement` + `textContent` only — never `innerHTML` with item data. A URL that isn't `http:`/`https:` renders the title as plain text.
- Colors as CSS variables on `:root`, dark values under `@media (prefers-color-scheme: dark)`; readable at 360px width, no horizontal scroll.
